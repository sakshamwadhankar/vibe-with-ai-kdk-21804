# 🚀 AI Mock Interview Platform — Hackathon Pitch & Judge Q&A Guide

---

## 1. ⏱️ The 30-Second Elevator Pitch (Memorize This!)

> *"Good day judges! We built an **AI-Powered Mock Interview Platform** designed to solve a huge problem: interview anxiety and lack of affordable, structured interview practice for candidates.*
> 
> *Our app lets users enter a specific Job Title, Tech Stack, and Experience Level. The system uses **Google Gemini AI** to generate realistic interview questions. Candidates answer in real-time using their **webcam and voice-to-text**, and our AI immediately evaluates their answers — giving them a **rating, detailed feedback, and the ideal model answer**.*
> 
> *It's fast, interactive, and acts like a 24/7 personal interview coach."*

---

## 2. 🔄 How the App Works (Step-by-Step Flow)

If judges ask: *"Walk me through the user flow,"* explain these 4 steps:

1. **Dashboard & Configuration:** 
   The user logs in via Clerk authentication, clicks *"Add New Interview"*, and enters:
   - **Job Position** (e.g., *Full Stack Developer*)
   - **Tech Stack / Job Description** (e.g., *React, Node.js, PostgreSQL*)
   - **Years of Experience** (e.g., *2 years*)

2. **AI Question Generation:** 
   Next.js sends a prompt to our custom serverless API (`/api/ai/generate`), which queries **Google Gemini 1.5 Flash**. Gemini returns a structured JSON array of technical & behavioral questions with ideal reference answers.

3. **Interactive Speech & Video Session:** 
   The user turns on their webcam (`react-webcam`) and speaks their answer into the mic (`react-hook-speech-to-text`). The speech is converted to text in real-time.

4. **AI Evaluation & Feedback Dashboard:** 
   Once submitted, Gemini compares the candidate's spoken answer against the expected answer, generates an instant rating (e.g., 8/10), points out strengths/weaknesses, and saves the session to a serverless PostgreSQL database (Neon + Drizzle ORM).

## 4. 🧠 Database Schema Design

We have two main relational tables in PostgreSQL managed by Drizzle ORM (`utils/schema.js`):

1. **`MockInterview` Table:**
   - `id`: Auto-incrementing primary key
   - `mockId`: Unique UUID string
   - `jobPosition`, `jobDesc`, `jobExperience`: Interview context
   - `jsonMockResp`: Full AI-generated Questions & Answers in JSON string format
   - `createdBy`: User email address
   - `createdAt`: Timestamp string

2. **`UserAnswer` Table:**
   - `id`: Auto-incrementing primary key
   - `mockIdRef`: References the parent interview `mockId`
   - `question`: The specific question answered
   - `userAns`: User's transcribed spoken text
   - `correctAns`: Ideal reference answer generated by AI
   - `feedback`: Detailed feedback & improvement suggestions
   - `rating`: Score out of 10
   - `userEmail`, `createdAt`: Session metadata

## 5. 🎯 Top 10 Questions Judges WILL Ask & Master Answers

### Q1: "How do you generate questions dynamically?"
**Your Answer:**
> *"We construct a prompt specifying the job position, job description, and years of experience, forcing the LLM to output strict JSON. We process this in our Next.js API route (`/api/ai/generate`) using Google Gemini 1.5 Flash."*

### Q2: "What database schema are you using?"
**Your Answer:**
> *"We have two main relational tables in PostgreSQL managed by Drizzle ORM: `mockInterview` (stores interview metadata and generated QA pairs) and `userAnswer` (stores candidate attempts, transcribed text, ratings, and feedback)."*

### Q3: "What happens if the Gemini API fails or runs out of quota?"
**Your Answer:**
> *"We designed a **hybrid fallback architecture** in `app/api/ai/generate/route.js`. If Gemini fails or API keys aren't set, our route automatically falls back to a local or remote **Ollama LLM model (e.g. Gemma 4 / Qwen)** so the application never breaks."*

### Q4: "How do you capture user speech?"
**Your Answer:**
> *"We use `react-hook-speech-to-text` which utilizes the Web Speech API directly in the browser to convert raw microphone input into transcribed text in real-time, which gets saved directly to our state and sent for evaluation."*

### Q5: "Is user data safe and authenticated?"
**Your Answer:**
> *"Yes, we use **Clerk** for session handling and user identity. Every interview session and score is linked directly to the authenticated user's email ID (`createdBy` / `userEmail` fields in DB)."*

### Q6: "Why Drizzle ORM over Prisma?"
**Your Answer:**
> *"Drizzle ORM has near-zero overhead, generates lightweight SQL queries, and integrates smoothly with serverless PostgreSQL providers like Neon without cold-start latency problems."*

### Q7: "How accurate is the evaluation?"
**Your Answer:**
> *"Gemini acts as a semantic grader. It doesn't just match keywords; it evaluates context, completeness, and clarity by comparing the user's transcription against the model answer and returning feedback in a JSON structure containing ratings out of 10."*

### Q8: "What makes this different from generic ChatGPT?"
**Your Answer:**
> *"ChatGPT is a generic chat box. Our platform simulates a **real interview environment** with webcam feed, voice recording, structured timing, step-by-step scoring, session history tracking, and actionable area-by-area feedback reports."*

### Q9: "What are the future enhancements / roadmap?"
**Your Answer:**
> 1. *"**AI Resume Parser:** Uploading a PDF resume to generate tailored questions automatically."*
> 2. *"**Text-to-Speech (AI Voice Interviewer):** Having an AI voice read the questions aloud to the user."*
> 3. *"**Emotion & Confidence Analysis:** Analyzing facial expressions via webcam during answers."*

### Q10: "Can this scale to thousands of users?"
**Your Answer:**
> *"Yes! Next.js 15 deploys serverlessly (e.g., Vercel), Neon handles autoscaling database connections, Clerk offloads authentication server load, and Gemini/Ollama handles distributed AI inference."*
